# كل التحسينات في المشروع — من الألف إلى الياء

> هذا الملف يشرح **كل** ما سيتم في المشروع، بالترتيب، وبلغة واضحة.
> التنفيذ نفسه في برومتس المراحل داخل `phases/`. الأدلة والتحليل في `docs/audit/2026-10-30-system-gap-analysis/`.
> كل بند له رقم مهمة (مثل `R1-A3`) يطابق البرومت والـ tracker.

---

## الصورة الكاملة في سطر واحد

نحوّل المشروع من **"Backend قوي + واجهة عرض تجريبية"** إلى **"منصة SaaS تعليمية حقيقية"**: آمنة، كل مستخدم يرى ما يخصه فقط، كل ميزة تعمل end-to-end ببيانات حقيقية، والحالة مثبتة بالأدلة.

## ترتيب المراحل

| المرحلة | الاسم | لماذا في هذا الترتيب |
|---|---|---|
| R0 | الاحتواء الأمني | ثغرات تسمح بدخول أي مؤسسة — لا شيء قبلها |
| R1 | نموذج الوصول (أدوار، صلاحيات، أقسام، تنقل) | كل الصفحات تعتمد عليه؛ يحل مشكلة "كل الصفحات لكل الأدوار" |
| R2 | إدارة المستخدمين وتجهيز المؤسسات | بدونه لا يمكن تشغيل المنصة فعليًا |
| R3 | الدفع ← الوصول | الاشتراك يجب أن يتحكم في المحتوى |
| R4 | المحتوى التعليمي + Drive + التقدم | قلب الـ LMS |
| R5 | الحضور و QR | قلب التعليم الحضوري |
| R6 | التقييم | امتحانات وواجبات حقيقية |
| R7 | إعادة تصميم UI/UX لكل دور | فوق دومين حقيقي، لا فوق بيانات فارغة |
| R8 | الإشعارات، التقارير، التحليلات، Meet | إغلاق الحلقات |
| R9 | التحقق والإطلاق | إثبات الحالة بالأدلة |

## R0 — الاحتواء الأمني

| # | ما سيتم | النتيجة للمستخدم |
|---|---|---|
| R0-1 | قفل كل endpoints المنصة (`/tenants`, `/platform/*`, إصدار توكن الدعم) خلف مصادقة منصة | لا أحد من خارج فريق المنصة يستطيع إنشاء/تعديل مؤسسات أو الدخول إليها |
| R0-2 | إخفاء `correct_answer` من كل الردود، وعدم إرجاع أسئلة الامتحان قبل بدء المحاولة | الطالب لا يرى الإجابات |
| R0-3 | فحص الملكية/الصلاحية في عرض طلب الدفع | لا أحد يرى إثبات دفع طالب آخر |
| R0-4 | صلاحية `audit.view` على سجل التدقيق | الطلاب لا يرون نشاط الإدارة |
| R0-5 | إيقاف تمرير توكن الدعم في الرابط (كود لمرة واحدة) | التوكن لا يظهر في السجلات |
| R0-6 | إصلاح استبدال الجهاز (لا بصمة عشوائية) | الطالب لا يُقفل خارج حسابه |
| R0-7 | لوحة المنصة تعرض حالة الصحة الحقيقية (لا "HEALTHY" وهمي)، وعنوان الـ API من الإعدادات | لا تضليل |
| R0-8 | فحوصات الثغرات في CI تفشل فعلًا | Gate أمني حقيقي |
| R0-9 | التأكد أن Google Client Secret غير موجود في أي ملف frontend | لا تسريب أسرار |

## ما لن يتغير

- عزل قاعدة بيانات لكل مؤسسة (يعمل ومختبر).
- طبقة الـ Provider Abstraction (صحيحة معماريًا؛ فقط الـ adapters ستصبح حقيقية).
- فصل Payment / Subscription / Entitlement في النموذج.
- العلامة المائية المتحركة على الفيديو.
- RTL والخط العربي.

## الحالة النهائية المستهدفة

- 0 مشاكل P0، و 0 متطلبات BROKEN أو SIMULATED في نطاق الإصدار.
- كل متطلب في `04-capability-coverage-matrix.md` = REAL أو مؤجل بقرار موثق.
- `current-state.md` = PRODUCTION_READY **فقط** عندما يمر Release Gate الجديد (R9-6).
