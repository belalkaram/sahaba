## 2. الهدف ومعايير النجاح

صفحة تسويقية بمستوى منتج عالمي، بهوية سحابة (زمردي + رملي، خليجي حديث)، تحكي قصة المنتج الفعلي، وتعرض الأكاديميات والمعلمين الحقيقيين باحتراف، وتتحرك بسلاسة تامة.

**معايير قبول رقمية (تُقاس ولا تُدّعى):**

| المعيار | الحد |
|---|---|
| Lighthouse (موبايل، build إنتاج) | Performance ≥ 90 · Accessibility ≥ 95 · SEO ≥ 95 |
| LCP | ≤ 2.0s |
| CLS | ≤ 0.02 (لا قفزات عند وصول البيانات أو الخطوط) |
| INP | ≤ 200ms |
| سلاسة التمرير | لا إطار > 32ms أثناء تمرير الصفحة كاملة (قياس Performance trace على 1440 و390 مع CPU ×4) |
| axe | 0 مخالفة critical/serious على الوضعين |
| reduced-motion | كل المحتوى ظاهر ومقروء بلا حركة |
| بلا JavaScript | كل النص والروابط ظاهرة (الحركة تحسين فقط) |
| المتصفحات | Chrome، Safari iOS، Firefox، Samsung Internet |

## 3. قرارات معمارية

1. **الصفحة Server Component** والبيانات (أكاديميات، معلمون، أسعار، أرقام) تُجلب على الخادم مع إعادة تحقق دورية (ISR). الحركة «جزر» client صغيرة فقط. **قبل الكتابة تُقرأ أدلة Next 16 المرفقة** (caching / cache components) كما يلزم `apps/web/AGENTS.md`.
2. **تحويل المستخدم المسجّل** ينتقل من `useEffect` إلى `middleware` (كوكي `lms_auth_token` موجودة) فلا تومض الصفحة له.
3. **الحركة لا تخفي المحتوى أبداً بدون JS:** الحالة الابتدائية للعناصر المتحركة تُضبط بـ CSS تحت صنف `html.motion-ready` يُضاف بسكربت inline قبل الرسم؛ بدون JS أو مع reduced-motion يبقى كل شيء ظاهراً. هذا يلغي الوميض (المشكلة 4).
4. **GSAP فقط**، يُحمَّل ديناميكياً لهذه الصفحة: `ScrollTrigger` + `SplitText` + `DrawSVG` + `Flip`. لا مكتبة smooth-scroll (Lenis وأمثالها): التمرير الأصلي أسلس على الأجهزة الضعيفة وأسلم مع RTL وإمكانية الوصول.
5. **العربية و SplitText:** التقسيم بالكلمات والأسطر فقط، **ممنوع بالحروف** (يكسر اتصال الحروف العربية).
6. **قواعد الأداء:** تحريك `transform`/`opacity` فقط؛ `will-change` لحظياً؛ لا `backdrop-filter` ولا `mask` على مساحات كبيرة متحركة؛ النقش الهندسي يصير SVG ثابتاً (inline، يُرسم مرة) بدل القناع؛ لا حركة `repeat: -1` إلا شريط الشعارات (CSS، يتوقف عند hover وخارج الشاشة وreduced-motion).
7. **المشاهد المثبّتة (pin)** على الشاشات ≥ 1024px فقط عبر `gsap.matchMedia()`؛ الموبايل يحصل على reveal بسيط وسكك أفقية بـ scroll-snap أصلي.
8. **الصور:** `next/image` بأبعاد ثابتة و`sizes`، والـ fallback المعماري الحالي (حرف على نقش) يبقى. يتطلب ضبط `images.remotePatterns` لمسار صور الـ API.
9. **الانتقال بين القائمة والتفاصيل:** `<ViewTransition>` من React (مدعوم في Next 16 بلا إعداد) لتحويل بطاقة الأكاديمية/المعلم إلى رأس صفحته، مع تراجع تلقائي إلى تنقل عادي في المتصفحات غير الداعمة.
10. **الصدق (OD-21 وقواعد الاستعادة):** أي رقم على الصفحة إما حقيقي من الـ API أو لا يُعرض. الأقسام التي لا بيانات لها (آراء، شعارات) تُخفى بدل عرض عينات عند الإطلاق.

## 5. الأكاديميات والمعلمون (الجزء الأهم)

### 5.1 صفحات جديدة
- `/academies`: دليل الأكاديميات — بحث، فلترة بالمدينة والنوع (معلم مستقل / مركز / أكاديمية / مدرسة / معهد) والخدمة (أونلاين/حضوري)، ترتيب (المميّزة أولاً).
- `/teachers`: دليل المعلمين — بحث بالاسم والتخصص، فلترة بالمدينة والأكاديمية.
- كل الحالات مصمّمة: تحميل (Skeleton بنفس أبعاد البطاقة)، فارغ، خطأ مع إعادة المحاولة، لا نتائج للبحث.

### 5.2 تطوير `/a/[slug]` وصفحة المعلم والمقرر (Quality Gate §11)
رأس بهوية الأكاديمية (شعار، اسم، نوع، مدينة، شعار نصّي)، أرقام حقيقية، نبذة، المقررات، المعلمون، بيانات التواصل (ما وافقت الأكاديمية على نشره فقط)، وCTA «سجّل في هذه الأكاديمية» يربط بمسار التسجيل الحالي (`/public/registration`). انتقال shared-element من البطاقة إلى الرأس.

### 5.3 المطلوب من الـ Backend (بنفس قواعد الخصوصية الحالية: opt-in فقط) — **نُفِّذ في L1**
| الطلب | السبب |

## 9. قرارات مطلوبة من المالك

1. **المحتوى الحقيقي:** أرقام، آراء، شعارات. البديل المقترح: أرقام حيّة من النظام وإخفاء الآراء والشعارات حتى تتوفر.
