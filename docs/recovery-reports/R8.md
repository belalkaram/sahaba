## 2. What changed

- **Migrations:** tenant `2026_11_05_000001` (preferences, tenant settings), tenant `2026_11_05_000002` (snapshot metrics become nullable, adds lesson completion and last activity); control `2026_11_05_000001` (`tenant_metric_snapshots`). All reversible. On rollback, the nullable change is not reverted.
- **New commands:** `lms:migrate-tenants`, `lms:notify-scheduled`, `lms:compute-analytics`, `lms:refresh-platform-metrics`.
- **Endpoints:**
  - `GET|PUT /me/notification-preferences` (any signed-in user, own data)
  - `GET|PUT /tenant/academic-settings` (`tenant.settings`)
  - `GET /analytics/at-risk`, `/analytics/courses/{id}`, `/analytics/classes/{id}` (`analytics.view` + per-resource scope)
  - `GET /reports/{id}/file` (owner or tenant-scope `reports.download`)
  - `POST /platform/metrics/refresh` (`platform.auth`)
- **Changed behavior:**
  - `GET /students/{id}/dashboard` returns `status: not_computed` and `dashboard: null` when no snapshot exists.
  - `POST /reports` queues the report and enforces data scope in the controller.
  - `GET /meetings` hides links from students and parents and lists only their own.
  - `GET /meetings/{id}/join` enforces `ContentAccessPolicy` and a time window.
  - The `api` rate limit is now per token (300/min), or per IP (60/min) when anonymous.

## 4. Behavior verified in the browser

- Real notification through `NotificationService`: bell showed one unread, and the dropdown showed the Arabic text and relative time.
- Report: requested in `/admin/reports`, stayed `queued`, a real `queue:work` processed it, the page updated by polling, the CSV had real data, and the file endpoint returned 401 without a token.

**Not exercised in the browser:** the student meetings page with real meetings and a real join, submitting the teacher meetings form, parent reports, the printed output, and saving a notification preference. These paths have backend tests where applicable, but no UI run.

## 5. Not done / limitations

- Real Google Meet events (R8-6) and real email delivery: needs Google Calendar API and SMTP credentials. Mail currently goes to the `log` mailer.
- PDF reports: see §7. Browser print is available.
- CSV import still runs inside the request.
- Course and class analytics have no UI; metrics definitions UI not built.
- Without a running worker and scheduler, reports stay queued and scheduled notifications are not sent.
- Existing tenants need `php artisan lms:migrate-tenants` (run locally for `almustaqbal`).
- `GET /reports/{id}/file` is an authorized stream rather than the signed URL the phase prompt describes: it needs the same token on every request, so there is no shareable link.

## 6. Discovered and fixed in this phase

- **No notification was ever sent** anywhere in the code; the bell could not have shown anything.
- **`joinUrl` skipped `canJoinMeeting`**, and `GET /meetings` exposed `join_url` and `host_url` to anyone with `meetings.view`.
- **Any non-401 error on session restore deleted the token**, so a 429 logged the user out; the rate limit was per IP because it runs before authentication. This caused the "reload sends me to login" behavior from the first audit.
- **Fabricated values:** dashboard 100% fallback; 100% for metrics with no data; assignment completion counted every assignment in the tenant, not enrolled courses; generated Google Meet codes that lead to no meeting; a teacher page claiming "Google Meet API enabled" with a hard-coded client ID; a simulated student classroom with fake chat; `simulate_failure` in production code; "last watched: recently" and course progress taken from the overall score.

## 6a. Discovered, not fixed

- Many pages still use `.catch(() => [])` (Operating Rule §4).
- `credential.issued` audit payload stores the credential code (not the secret).
- The console logged `Service Worker registration failed` in the browser pane, while `/sw.js` is valid and served with 200. Cause not determined; check in a normal browser.
- C: drive of the dev machine is at 99% (1.6 GB free); one test run failed with `No space left on device` and passed on retry.
- `access_test_*` and `tenant_test-school*` test databases accumulate in `apps/api/database/tenants` (about 400 MB) because those tests do not close the connection before deleting. Not touched.
- `ZoomMeetingProvider` and `MockMeetingProvider` fabricate links: blocked outside the `testing` environment, code kept for tests.
