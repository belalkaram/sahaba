## 1. Executive Summary

Phase R5 implements the production-grade physical and electronic attendance system for the LMS:
1. **Dynamic Student QR Token (R5-1):** Time-bounded (exp ≤ 60s), HMAC-SHA256 signed, URL-safe opaque token derived from `app.key` + `tenant_id`. No raw student codes or secret credentials are ever exposed in the QR payload.
2. **Server-Authoritative Scanner & Attendance Engine (R5-2):** Strict multi-step validation sequence (tenant boundary → permissions/branch scope → session active status → timing mode & grace period window → cryptographic token verification → active student status → class roster enrollment check → deterministic idempotent duplicate recording → audit logging).
3. **Session QR (R5-3):** Deferred per Open Decision OD-4 (teacher screen QR projection) in favor of the primary physical workflow: Student Card scanned by Teacher/Assistant mobile device.
4. **Attendance Corrections & Audit Trail (R5-4):** Manual and automated recording modes. Corrections require an explicit reason and are permanently archived in the `attendance_record_changes` history table with the actor's identity. Session lifecycle controls (`start`, `end`, `cancel`).
5. **Student "My Card" Screen (R5-5):** `/student/card` high-visibility digital ID card with real-time countdown, auto-refreshing QR code, screen brightness hint, and tenant branding.
6. **Mobile Camera Scanner (R5-6):** `/teacher/attendance/scan/[sessionId]` responsive mobile scanning console with real camera feed, camera flip, torch toggle, Web Audio API sound confirmation, haptic vibration, live result toast, running stats counter, and manual search fallback.
7. **Offline Structure & Control Rooms (R5-7):**
   - `/student/attendance`: Complete personal attendance history with per-class rates and session breakdown.
   - `/teacher/classes`: Classes management with branch filtering and modal creation.
   - `/teacher/classes/[id]`: Roster management (enroll/remove students) and session scheduling.
   - `/teacher/sessions`: Sessions catalog with status tabs.
   - `/teacher/sessions/[id]`: Live session control room with real-time roster, quick status mark, correction modal with mandatory reason, and full audit history drawer.

## 3. Cryptographic Token & Verification Engine

### 3.1 Student QR Token Structure (`StudentQrService`)

- **Payload:** `{"sub": student_id, "tenant": tenant_id, "iat": timestamp, "exp": timestamp, "nonce": random_hex, "cid"?: class_id}`
- **Signing:** `hash_hmac('sha256', base64_payload, hash('sha256', app.key . tenant_id))`
- **Transport:** URL-safe Base64 token (`payload.signature`).
- **Security Invariants:**
  - Token expiration enforced strictly (`exp ≤ 60` seconds).
  - Tamper detection: any modified byte invalidates HMAC verification (`INVALID_TOKEN_SIGNATURE`).
  - Tenant boundary enforced: token issued for Tenant A is rejected by Tenant B (`TENANT_MISMATCH`).
  - Device/credential check: students with revoked credentials cannot generate or validate QR tokens.
  - No static student codes allowed unless tenant explicitly enables `allow_static_student_code_scan`.

### 3.2 Attendance Validation Sequence

1. **Tenant Scope Check:** Authenticated staff belongs to active tenant.
2. **Permission Check:** Staff has `attendance.mark` and class branch scope access.
3. **Session Status:** Session must be in `scheduled` or `in_progress` status.
4. **Time Window Check:** In `scheduled` mode, current time must be within `starts_at - 15m` and `ends_at + grace_period_minutes`.
5. **Token Cryptographic Validation:** Valid signature, within 60s validity, matching tenant ID.
6. **Student Active State:** Student profile exists and status is `active`.
7. **Class Roster Check:** Student is enrolled in `class_students` for the session's class.
8. **Deterministic Idempotence:** If student is already recorded in the session, returns `200 OK` with `already_recorded: true`, avoiding UX disruption.
9. **Record Creation:** Created on `attendance_records` with `recorded_by_user_id` and `attendance_mode: 'qr'`.
10. **Audit Log:** Recorded via `AuditLogger::log()`.
