# Recovery Phase R3 Report — Billing-to-Access Bridge

**Status:** COMPLETE & VERIFIED
**Date:** 2026-10-31
**Domain Owner:** Billing, Tenancy & Content Access Control

---

## 1. Executive Summary

Phase R3 establishes the critical, secure bridge connecting commercial transactions (packages, payments, subscriptions) with academic access control (courses, lessons, enrollments, exams).

Previously:
- Self-enrollment was open and bypassed payment checks.
- Courses and lessons lacked server-side access enforcement; any authenticated student could load paid lessons.
- Payment requests did not support secure proof file upload and private inspection.
- Package and entitlement management lacked full lifecycle APIs (updating packages, archiving, manual entitlement grants with audit logs).
- Frontend lacked dedicated student billing screens (`/student/plans`, `/student/plans/[id]/pay`, `/student/payments`, `/student/subscriptions`) and administrative package pricing screens (`/admin/packages`).

Phase R3 solves this comprehensively across backend and frontend with zero simulated mocks and zero security compromises.

## 2. Implemented Architecture & Components

### 2.1 Backend Domain & Policies

1. **`ContentAccessPolicy` & `ContentAccessDecision` (R3-1):**
   - Authoritative policy evaluating access to courses, lessons, and exams.
   - Core Invariants:
     - Staff members with appropriate teaching/management rights bypass student paywalls.
     - Unpublished/draft content is denied to students (`draft`).
     - Free preview lessons (`is_free_preview = true`) are always accessible to authenticated users.
     - Free courses (`is_free = true`) are accessible once enrolled.
     - Paid courses require:
       1. Active enrollment.
       2. Active, non-expired entitlement matching `course:{course_id}`, `all_courses`, or `ONLINE_ACCESS`.
     - In case of lock, returns structured decision `{ allowed: false, reason: 'not_enrolled' | 'no_entitlement' | 'expired', required_package_ids: [...] }`.
   - Integrated into `CourseController@index`, `CourseController@show`, `LessonController@index`, and `LessonController@show` (returning 403 `ACCESS_REQUIRES_SUBSCRIPTION` when denied).

2. **Gated Self-Enrollment (R3-2):**
   - Modified `EnrollmentController@store`.
   - Students can self-enroll only if the course is marked `is_free` or if they already hold a valid entitlement covering the course.
   - Otherwise, requests are rejected with 403 `ENROLLMENT_REQUIRES_PAYMENT`.

3. **Secure Payment Proof Upload (R3-3):**
   - Updated `PaymentRequestController@store` to support multipart `proof` upload (JPEG, PNG, PDF up to 5MB).
   - Stored in private, tenant-isolated disk storage (`tenants/{slug}/proofs/`).
   - Secure private streaming endpoint `GET /api/v1/payment-requests/{id}/proof` gated by strict authorization boundary: only the student who owns the payment request or authorized staff reviewers can access the proof.

4. **Package Lifecycle & Manual Entitlements API (R3-4):**
   - `PackageController`:
     - `update`: Updates pricing, billing cycle, description, and synchronizes package entitlements.
     - `archive`: Soft-archives packages to hide them from new subscriptions while preserving existing active subscriptions.
   - `EntitlementController`:
     - `grant`: Grants manual entitlements with mandatory reason and optional expiration, recorded in `AuditLogger` with action `entitlement.granted`.
     - `revoke`: Revokes active entitlements with mandatory audit reason, recorded in `AuditLogger` with action `entitlement.revoked`.
   - `MyResourceController`:
     - `GET /me/subscriptions`: Active subscriptions for authenticated student.
     - `GET /me/entitlements`: Active, non-expired entitlements for authenticated student.

5. **Approval Side Effects & Transactional Auto-Enrollment (R3-7):**
   - In `PaymentReviewService@approve`:
     - Updates payment status to `approved`.
     - Activates `Subscription`.
     - Grants `Entitlement` records matching the package.
     - **Side Effect:** Automatically creates `Enrollment` records for any specific course entitlement (`course:{id}`), immediately unlocking access without requiring manual student action.

## 4. Security Invariants Preserved
- No student can view paid course or lesson content without an active, non-expired entitlement verified on the backend.
- Payment proof files are stored privately on local disk under tenant namespaces and streamed only to authorized users.
- Manual entitlement grants and revocations require a mandatory reason and are written to the audit log (`entitlement.granted`, `entitlement.revoked`).
- Frontend checks are strictly for UI visibility; backend is the authoritative enforcement point.
